# ADR 0004: Protocol Gary as a Separate-Call Forced Audit (Not Inline System-Prompt Augmentation)

| Field | Value |
| --- | --- |

## Context

Soft prompting ("be careful"; "list risks before acting") demonstrably fails for high-stakes operations. The model produces compliant text and proceeds anyway. Hard enforcement is needed. Multiple designs are possible:

1. **Inline system-prompt augmentation**: Tsukuyomi rewrites the agent's system prompt to include "before any high-risk action, list risks." The agent's same LLM call produces both the analysis and the action. The augmentation is hopeful; the agent can still skip the analysis or paper-mâché it.
2. **Forced "thinking" tokens**: Tsukuyomi requires the agent to emit a structured `<thinking>...</thinking>` block. Validation of the block is post-hoc. The agent can produce valid-shape but vacuous content.
3. **Separate-call structured audit**: Tsukuyomi intercepts before the agent's response reaches the user, makes a *separate* LLM call (its own, on Tsukuyomi's side) with a structured audit prompt, validates the answer programmatically, blocks passage on failure.

Patterns 1 and 2 are *cooperative*; they require the agent to play along. Pattern 3 is *coercive*; the agent does not need to cooperate because the audit is run by Tsukuyomi against the agent's plan, with Tsukuyomi controlling validation.

## Decision

**Protocol Gary is a separate-call structured audit (pattern 3).** Activated on Tier 3 / HIGH+CRITICAL blast-radius / irreversible-keyword / multi-step-plan triggers. Five-question structure. Deterministic validation. Two rounds maximum, then Mouth escalation.

Full specification: `docs/architecture/04_protocols.md` §5.1.

## Rationale

### Coercion

The audit-LLM call is on Tsukuyomi's side, with Tsukuyomi's prompt and validation. The agent does not see the questions; the agent does not get to choose how to respond. Tsukuyomi sends the agent's plan to the audit LLM and asks the audit LLM the five questions about that plan. The audit LLM's role is structurally separate.

Critically, this also means the audit can use a *different* LLM from the one the agent uses. A Tier 3 plan generated by `claude-sonnet-4.5` can be audited by `claude-haiku-4.6` (cheaper) or `gpt-5.2` (different family — and therefore independent failure modes). This composability is impossible with cooperative pattern 1.

### Determinism in validation

The audit's validation rules are deterministic (length thresholds, evasion-phrase blocklist, risk-keyword count). Decision *to pass or block* is not made by an LLM; it's made by a Python function. This protects against the "valid-shape vacuous content" failure mode of pattern 2: vacuous content fails the deterministic rules.

### Round structure

A failed round 1 does not block permanently because the audit's purpose is to *force engagement*, not to punish first-attempt verbosity. Round 2 is given specific feedback ("Q1 too short, missing risk vocabulary") so the agent can improve. Round 2 failure → Mouth escalation, which puts a human in the loop. Two rounds is calibrated empirically to (a) be enough for genuine attempts to refine, (b) be few enough that adversarial agents cannot grind the validation rules.

### Naming

The reference to *Gary* in *Bird Box* (2018) is mnemonic, not decorative. Gary's role in the film is to *force other characters to confront uncomfortable truth* by removing their blindfolds. Tsukuyomi's Protocol Gary forces the agent to confront the uncomfortable specifics of how its plan could fail. The name is short, memorable, distinctive, and carries the right semantics.

## Alternatives considered

### A. Inline system-prompt augmentation

**Rejected.** Cooperative; bypassable; track record from existing approaches is poor.

### B. Forced "thinking" tokens

**Rejected as primary mechanism.** The structural problem — the agent might produce shape-valid but content-vacuous text — is not solved by mandating the shape. It is solved by validating content (which Gary does) and by validating against an external LLM (which Gary also does).

### C. Separate-call structured audit

**Selected.**

### D. Multi-LLM consensus (e.g. ask 3 different LLMs and require majority refusal)

**Considered.** More robust than single-audit-LLM, but 3x more expensive, slower, and the marginal safety gain over single-call audit + sandbox + Mouth escalation is unclear. Deferred to v1.1 as an optional `gary.consensus_mode`.

## Consequences

### Positive

- Coercive, not bypassable.
- Allows audit-LLM to be a different model (cross-family independence).
- Validation is deterministic; pass/block is not at the discretion of an LLM.
- Round structure allows productive refinement without indefinite retry.

### Negative

- Adds one LLM call to every Tier-3 request: ~1500 input + 800 output tokens, ~$0.02–0.05 cost, ~5–20 second latency.
- Validation rules are heuristic; tuning them against false positive/negative rates is ongoing work (NightShift heuristics 1 and 2).
- The five questions are static in v1.0; future versions may select questions based on operation type.

## Compliance

PRs that propose any of the following must amend this ADR:

- Removing the separate-call structure in favor of inline augmentation.
- Adding a "skip Gary" flag bypassable by agent prompts.
- Lowering validation strictness without explicit calibration evidence.
